# Aether governance

Aether currently uses a maintainer-led, consensus-seeking governance model.
The `SingularityCoLabs` organization owns the project, and repository access
on GitHub is the authoritative record of current maintainers.

## Roles

### Contributors

Anyone who improves code, tests, documentation, issue triage, design, or
community support is a contributor.

### Maintainers

Maintainers review and merge changes, triage reports, manage releases and
security disclosures, enforce community standards, and protect Aether's
architectural and security invariants.

Maintainer status is earned through sustained, constructive contributions and
sound judgment. Existing maintainers decide when to grant or remove repository
access based on the project's needs.

## Decisions

- Routine changes are decided through issue and pull request review.
- Maintainers seek consensus and explain material tradeoffs.
- A maintainer makes the final decision when consensus cannot be reached.
- Changes to public contracts, trust boundaries, storage semantics, provider
  behavior, or architectural invariants require an ADR under `docs/decisions`.
- Security response and Code of Conduct enforcement may remain private to
  protect reporters and affected people.

## Releases

Maintainers decide when a roadmap phase satisfies its implementation, test,
observability, security, and documentation gates. Until the first stable
release, compatibility may change through documented pull requests and ADRs.

## Amendments

Governance changes use the normal pull request process and require maintainer
approval.
